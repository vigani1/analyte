# Byte-reader fuzzing

Run on Linux with cargo-fuzz 0.13.2 and nightly-2026-11-14:

```sh
cargo +nightly-2026-11-14 fuzz run lis01 -- -max_total_time=60 -timeout=10 -rss_limit_mb=1024 -max_len=2097152
```

CI runs every target independently. Time and RSS limits detect hangs and excessive
allocation; decoder pending-buffer assertions check their documented bounds.
Targets use API defaults where available. MLLP and POCT require explicit limits:
1 MiB messages, POCT depth 32, 16384 elements and 4096 attribute bytes. VIDAS
uses Literal mode, 80-byte chunks, 1920-byte messages, no suffix, checksum excluding
STX/suffix and accepting either hex case. Autolyser exercises framing through its
dialog with a fixed clock and 64000-byte response bound; it has no separate framer.

Successful lossless parses assert exact source retention. Recordings round-trip
typed events (JSON whitespace is not retained). Contract decoding validates typed
JSON documents; lexical JSON whitespace is not promised. HL7 accepts both editions
through the same parser; both synthetic versions are seeded.

Seeds come only from synthetic tests, sim recordings and contract vectors already
in this repository. HL7 2.3.1 seed changes only the edition of the synthetic 2.5.1
fixture. LAW seeds are generated by `cargo run -p analyte-hl7 --example law_messages -- fuzz/corpus/law`.
Rust byte literals from XML and vendor protocol tests include deliberate
malformed cases. No vendor manuals or patient captures are included.

libfuzzer-sys 0.4.13 ((MIT OR Apache-2.0) AND NCSA, rust-fuzz/libfuzzer) is isolated here. Its
build script compiles bundled LLVM libFuzzer C++ using cc; dependencies include
arbitrary and build support cc. It does not enter the main workspace lockfile,
MSRV, stable toolchain or cargo-deny graph. Windows can check these harnesses,
but sanitizer fuzz runs are performed by Linux CI.
