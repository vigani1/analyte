# Analyte desktop app: design handoff

Analyte connects a medical lab's analyzers to the lab's software ("lab app").
The engine (a background service) does the work. This package is the design
for the **Analyte app**: the desktop window and tray icon that show what the engine is doing.
Users are lab managers and senior technicians, so use plain words and no jargon.

## What's in this folder

| Path | What it is |
|---|---|
| `css/analyte.css` | **The design system.** Tokens (CSS custom properties) + all component classes. Use as-is. |
| `css/fonts.css` | `@font-face` for the bundled fonts. Put the .woff2 files in `css/fonts/` (see below). |
| `icons/` | App icon + 3 tray icons (all good / needs you / engine stopped), SVG. |
| `mockups/*.dc.html` | One file per screen or state: the visual reference. See "Reading the mockups". |

## Build rules

- Screens are HTML generated by the engine, styled **only** with `css/analyte.css`, plus one small script for live updates.
- **No CSS framework, no React.** Everything is bundled; nothing loads from the internet.
- Load order: `fonts.css`, then `analyte.css`.
- Colours: use **semantic tokens only** (`--bg`, `--surface`, `--text`, `--accent`, `--good-text`, `--bad-bg`, ...), never the `--p-*` primitives or raw hex.
- Theme: light by default; dark follows the OS automatically (`prefers-color-scheme`). `data-theme="light|dark"` on any element forces a theme.
- Status is **never colour alone**: always an icon + a word (`.status .status--good|warn|bad|off`).
- Numbers (times, counts, sample IDs, ports) use `.mono` / `.num` / `<time>` so they line up.
- Icons: Lucide (ISC licence), inline `<svg class="icon" viewBox="0 0 24 24"><path d="..."/></svg>`. The exact paths are in the mockups' scripts.
- Motion: 150–250 ms. The only loops are the live dot pulse and the data dots on the signal path. Everything stops with "reduce motion" (already handled in the CSS).
- Window: about 1280×800, resizable to 900 px. Below 1000 px the sidebar becomes an icon rail (CSS container query on `.app`, already handled).
- Accessible: real `<button>`/`<a>`/`<input>`+`<label>`, visible focus (handled), keyboard usable, 4.5:1 contrast (tokens pass).
- Never show patient names or result values anywhere: sample IDs and counts only.

## Page skeleton

```html
<div class="app">
  <nav class="sidebar" aria-label="Main">…see mockups/Sidebar.dc.html…</nav>
  <main class="main">
    <header class="page-head"><div><h1>Overview</h1></div></header>
    …sections…
  </main>
</div>
```
Centered screens (sign in) use `<div class="center"><form class="panel">…</form></div>`.

## Reading the mockups

Each `mockups/X.dc.html` is a design-tool file, not production HTML:
- The markup between `<x-dc>` and `</x-dc>` is the real structure and classes. Copy it.
- `{{name}}` placeholders, `<sc-for list="{{items}}" as="item">` (a loop) and `<sc-if value="{{cond}}">` (a condition) are filled from
  `renderVals()` in the `<script type="text/x-dc">` at the bottom. That script holds the sample data, the
  icon paths and which state is shown. Turn these into your own templating.
- `<dc-import name="Sidebar" active="machines">` means "insert the sidebar with Machines selected".
- Files named `…Dark`, `…Good`, `…Empty`, `…Step2` etc. are thin wrappers that show another state of a screen.
- Ignore `<helmet>` (it only loads the fonts for preview) and `/_blob/…` stylesheet links (that is `analyte.css`).

## Live updates (behaviour)

- New activity lines are prepended with class `feed__line--new` (slides in, light accent tint).
- Connection state changes swap the `.status--*` class; colours transition smoothly (CSS).
- Signal path: a live wire is `.wire` with one or two `.wire__dot` children; waiting `.wire--wait`; broken `.wire--cut` with a `.wire__break` marker.
- The engine status in the sidebar is `.engine` (running) or `.engine.engine--stopped`.
