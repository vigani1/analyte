## Test-claim audit

Read AGENTS.md clinical rules 1–10, ADRs 0003, 0004, 0008, 0010 and
0011, plan sections 6, 7 and 10, and contract v1 (including its published
vectors). No analyzer protocol expectation was introduced or changed; the new
cases exercise the host's JSON/HTTP policy, not ASTM/HL7/LAW wire behavior.
Consequently no new standard/vendor conformance claim or evidence-level change
is made, and no protected reference text was copied.

| Claim / source | Audit conclusion and checks |
| --- | --- |
| Durable before ACK, rules 1–3 / ADRs 0003 and 0010 | Contract decoding and sink HTTP success are not analyzer ACK authorization. Analyzer custody remains a store/dialog/host responsibility. Existing sink tests enqueue through the real store before delivery; the reference peer exercises app acceptance. This round does not claim new crash/disk-full coverage at analyzer ACK boundaries. |
| Three identities and retry identity, rule 4 / plan §6–7 / ADR 0008 | Existing lost-response test compares both actual requests with the original stored ID and bytes; interrupted-shutdown test checks recovered claim ID and payload. New build test independently checks delivery, receipt, result observation/run and revision fields and exact sample/value text. It refuses unresolved identity. |
| No silent loss / rule 2 and ADR 0003 | Existing conflict test checks durable parked evidence and blocks the following correction. New response test requires the specific app reason, with version validation, rather than merely matching the word conflict. Invalid success cannot mark delivery done. |
| Values unchanged, rules 5–6 / contract v1 POST results | Published vectors compare independent expected JSON with model conversion. New accessors check decimal precision and explicit unit mapping; build test checks `<0.1`, `1,234`, `positive`, `ERROR` and leading-zero sample ID. No numeric conversion or dilution arithmetic is inferred. |
| Revisions / ADRs 0003 and 0011 | Contract represents revisions/statuses; sink keeps revision delivery order. Store assigns progression/correction revisions and owns not-reportable-result suppression. These tests do not claim to validate those store-owned tables or clinical reporting. |
| Configuration, authentication and bounded work / rule 7 / contract v1 | Independent invalid limits, inclusive ceilings, URL/auth fields, complete document size and bounded response bodies are challenged directly. New idle and stop tests guard the bounded waits. Header/secret ceilings are host policy, not analyzer-standard limits. |
| Cache trust / rule 9 / ADR 0004 / contract v1 GET orders | Existing test checks complete/fresh trust and 410 reset. New test independently checks repeated incomplete cursor refusal, repeated final cursor acceptance, page-count bound, page-size bound and cache trust; errors are never reclassified as no orders. |
| Existing contract test names | Renamed `all_result_evidence` to `published_result_vectors` and `every_interpretation` to `selected_interpretations`: those cases cover selected fixtures, not every possible value. Source prefixes remain ADR 0008 / clinical rules. No assertion was weakened or removed. |
