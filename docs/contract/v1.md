# App contract version 1

This is the JSON wire contract from ADR 0008. It is independent of the internal
clinical model. All examples are synthetic. Evidence level: documented; local
reference-peer tests do not establish interoperability with another app.

## HTTP and authentication

Use HTTPS with verified certificates. The example binary binds loopback HTTP
behind a TLS reverse proxy. Set ANALYTE_API_KEY and ANALYTE_SIGNING_SECRET in
the environment; run analyte-receiver --database receiver.sqlite --listen
127.0.0.1:8080. An optional --seed file contains an array of orders.

Every request uses Authorization: Bearer followed by the destination key.
POST requests additionally carry webhook-id (the delivery_id),
webhook-timestamp (integer Unix seconds) and webhook-signature. Standard
Webhooks v1 signs the exact bytes of id.timestamp.body with HMAC-SHA256.
Secrets use whsec_ followed by padded standard base64 of 24–64 random bytes.
The signature header contains space-separated v1,base64 candidates, allowing
senders to sign with old and new keys during rotation. A receiver accepts any
matching trusted signature, comparing MACs in constant time, and rejects a
timestamp more than 300 seconds in either direction.

Source: [Standard Webhooks 1.0.0, authenticity and metadata sections](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md).
The tests also use the project's published Rust signing vector.

Documents are UTF-8 JSON objects. Unknown fields are ignored. A complete input
document is limited to 1,048,576 bytes, including unknown fields. Text is never
trimmed or normalized. Envelope text is nonempty, at most 4096 UTF-8 bytes,
without NUL. Evidence identifiers and sample IDs are nonempty, at most 256 bytes,
without control characters. Reasons are nonempty, at most 1024 bytes, without
controls. Source text permits empty strings and controls, up to 16384 bytes.
Optional fields may be absent or null. Lists and other fields are required
unless marked optional. Each evidence list has at most 256 members.
Order versions are positive unsigned 64-bit integers. Result revisions are
unsigned 64-bit integers including zero. Every envelope has required integer
contract_version, exactly 1.

## POST /results

The required envelope fields are:

| Field | Type and meaning |
| --- | --- |
| delivery_id | RFC UUIDv7 string, stable across retries |
| created_at | Timestamp string with explicit offset |
| source | Object with analyzer and connection identifiers |
| receipt | Provenance object described below |
| results | Array of 1 to 1000 replacement units |

Receipt fields are required: id (RFC UUIDv7 string), received_at (timestamp
with offset), raw_sha256 (64 hex digits for original machine bytes), driver
(namespaced identifier), config_version (identifier), config_sha256 (64 hex
digits for retained configuration). A namespaced identifier is an object
with required namespace and value identifier strings. Code systems and order
assigning systems are never inferred from display labels.

Every replacement unit has these required fields:

| Field | Type and meaning |
| --- | --- |
| receipt | RFC UUIDv7 string, matching envelope receipt.id |
| sample | Optional sample object; null means unavailable, never a fabricated ID |
| processing | production, training, debug, quality_control, unknown |
| identity | Exactly one resolved or unresolved variant, described below |
| parts | Array of 1 to 256 source parts, in source order |

For processing `unknown`, the machine did not state it; never treat as production.

Sample has required id (exact string, retaining case and leading zeros),
source (scanned_by_machine, typed_on_machine, work_list, instrument_assigned,
unknown), and optional position. Position has required kind and slot
(identifier), and optional carrier (identifier). kind is rack, disk, tray,
or an object {"other":"source carrier kind"}.

Identity is {"resolved":{"observation":...,"revision":0}} or
{"unresolved":"specific reason"}. Observation has required code
(namespaced identifier), sub_id (source text, including empty), run (source
text: the machine's run evidence, empty when it gives none) and order
(namespaced identifier). Without run evidence a rerun cannot be told from a
retransmission, so Analyte parks differing content as a conflict. Revision is assigned by Analyte, independent of
source status. Corrections advance it; reruns have a new observation identity.
Unresolved identity and missing sample require operator reconciliation.

Every part has these fields:

| Field | Required | Type and meaning |
| --- | --- | --- |
| test | yes | Namespaced test code |
| values | yes | Array of 0 to 256 value objects; repeats retain order |
| units | no | Unit evidence object |
| dilution | no | Dilution evidence object |
| flags | yes | Array of source text strings |
| reference_range | no | Source text, uninterpreted |
| comments | yes | Array of source text strings |
| qc_class | yes | patient, control, calibration, unknown |
| source_status | yes | Source text as sent |
| status | yes | pending, preliminary, final, corrected, withdrawn, not_performed, unknown |
| source_path | yes | Array of hierarchy nodes in message-to-part order |
| times | yes | Array of named source times |
| received_at | yes | Host timestamp string with explicit offset |

Apps must not deliver withdrawn results as current. Keep their history and
remove the superseded observation from current reporting. An unknown summary
never replaces the original source status.

A value has required original (source text) and parsed (interpretation), and
optional decoded_text (source text, at most 16,384 UTF-8 bytes). The original
stays exactly as received and authoritative. decoded_text contains protocol-neutral
text only after complete decoding succeeds; apps never need HL7 escape knowledge.
It is absent for formatting/highlighting instructions or unsupported escapes:
those values retain their original spelling and carry an unsupported interpretation
with a specific reason, and the bridge parks the result with a finding. Never
present a partially decoded string as clean. An absent decoded_text differs from
an explicitly decoded empty string. Existing documents may omit the field.
Interpretations use a single-key object except text, which is the string
"text":

| Variant key | Required payload fields (optional fields noted) |
| --- | --- |
| numeric | number: exact decimal string; comparator: optional less, less_or_equal, greater, greater_or_equal |
| coded | code: namespaced identifier; text: original display source text |
| structured_numeric | comparator: optional comparator; first and second: optional decimal strings; separator: source text |
| attachment | media_type and encoding: identifiers; data: source text, retained encoded, never expanded |
| unsupported | source_type: identifier; reason: reason string; retain original and park |

Exact decimals have an optional + or - sign, digits, and optionally a decimal
point followed by digits, up to 256 bytes. No exponent, grouping separator,
NaN or infinity. All precision, leading zeros and sign spelling survive.
Original text remains authoritative beside interpretation, including error tokens.

Units has required original (source text) and optional mapping. Mapping has
required source (source text exactly equal to original) and target (configured
UCUM identifier). This is explicit mapping evidence, not inferred conversion
or terminology validation. Dilution has optional original (source text exactly as
written), optional factor (an exact decimal only when source parsing establishes
it), and required applied (yes, no, unknown). Retain ratios and other dilution
spellings without guessing a factor or application status. No multiplication
happens in the contract.

Each hierarchy node has required kind (identifier), optional sequence and
optional status (both source text). A named source time has required role
(identifier) and time (object). Time requires original (source text) and
precision (year, month, day, hour, minute, second, fractional_second, unknown).
Optional parsed is a local date-time string without offset; optional offset
is an integer number of UTC-offset seconds within -93599 through 93599.
No timezone is supplied for a partial or local source time.

The wire can represent all processing modes and parked evidence. This does
not authorize production delivery: senders must enforce the model's eligibility
rules before creating a production outbox entry. The reference receiver stores
evidence only and never publishes a patient report.

## POST /order-events

Required fields: contract_version, delivery_id, created_at and source have the
same meanings as results. order_id is the app's order string, order_version
is its positive integer version, occurred_at is an offset timestamp,
source_status is the exact source text. state is requested, sent, accepted, rejected,
done, cancel_requested, cancel_confirmed or uncertain. reason is optional text. An uncertain
event records an unknown outcome; it is never permission to resend an order.

## Delivery responses and retries

The receiver commits the ID, endpoint, exact document bytes and SHA-256 digest
in one SQLite transaction with synchronous FULL before reporting success.
Its worked-example effect is this durable receipt, not a clinical report.

| HTTP | Body/action |
| --- | --- |
| 200 | contract_version: 1 and status: accepted or duplicate; done |
| 409 | Same ID with different bytes or endpoint; park |
| 400 / 422 | contract_version: 1, error code string, detail reason string; park |
| 401 / 403 | Authentication failed; pause destination for setup repair |
| 408 / 429 / 5xx | Retry with capped exponential backoff and jitter |
| Other | Park; never follow redirects automatically |

Retry-After accepts delay seconds or an IMF-fixdate HTTP date. Malformed values
fall back to sender backoff. The classifier returns the requested delay; the
sender owns scheduling and jitter. Missing answers are retryable. Every retry
reuses the ID and exact body bytes, recomputing only signing metadata.

## GET /orders?cursor=opaque&limit=100

Bearer authentication is required. limit defaults to 100 and must be 1–100.
The cursor is optional, opaque text limited to 256 bytes. Without one, the
receiver pages the latest version of each order from a fixed snapshot.
Changes during paging are visible after the snapshot completes. With the
last cursor, the receiver pages subsequent changes, including tombstones.

Responses contain contract_version: 1, orders (array), next_cursor (string)
and complete (boolean). complete is true on the final page, even when the
array is empty. Retain next_cursor after the final page for the next poll.
Each cursor expires one hour after creation. An unknown or expired cursor
returns 410 with the versioned error body; reload a complete snapshot.
The client must commit each page with its cursor and keep its cache untrusted
until the snapshot is complete (ADR 0004). Only a poll that reaches the page
with complete true refreshes the cache's freshness, and it counts from when
that poll began, since changes made while it ran may be missing. A poll that
stops early leaves freshness where the last complete poll set it.

Each order requires id, positive version, state, sample_id (exact string),
tests (at most 100; each a namespaced identifier {"namespace": code system, "value": test
code}, never a bare string), priority (routine, urgent, stat),
and tombstone (boolean). State is requested, sent, accepted, done,
cancel_requested, cancel_confirmed, rejected or uncertain. Optional target_analyzers
is a nonempty list of at most 100 analyzer strings. Optional expires_at is an
offset timestamp. Tests are nonempty except on tombstones. A tombstone retains
the order ID and version so deletion cannot be mistaken for missing data.
An order's version only increases, and one version has one content: the
client keeps its cached order when offered a lower version, or the same
version with different content, and parks that offer for an operator.

### Optional order context

An order may supply `position`, `specimen_type` and `patient`. Absent or null
means unknown; the bridge never supplies a default. `position` uses the same
position object as result `sample.position`: required `kind` and `slot`, optional
`carrier`. `specimen_type` is a namespaced identifier with required `namespace`
and `value`, translated explicitly by the machine's outbound table. `patient`
has one required `id`, also a namespaced identifier. No patient name or other
demographics are included. Keep every identifier's spelling, case and leading
zeros. Patient context belongs only in protected evidence, never ordinary logs.
If the selected machine requires missing context, or a value exceeds its wire
limit, reject the order with a specific lifecycle event before transmitting.

Seeding uses the bounded library seed operation or --seed file. Seed files
contain at most 100 orders, within the document byte limit. No public admin
route exists. SQLite files contain protected data and require deployment-level
access control and backups. The example implements no clinical interpretation,
result mapping, TLS termination, sender outbox or analyzer order dispatch.

## Test vectors

vectors/generate.py deterministically writes synthetic JSON using Python's
standard library. Run `python -I docs/contract/vectors/generate.py` from the
repository root. signature.json holds the
exact body as a string, fixed secret, send time, expected signature and digest.
delivery.json, event.json and order.json show complete documents;
order-context.json adds optional order context while order.json stays minimal;
invalid-version.json must fail validation. responses.json records expected
sender decisions. Rust tests check documents, signatures, digests and outcomes.

Additional vectors: `accepted.json` is the accepted response; `duplicate.json`
is the duplicate response; `invalid-signature.json` exercises signature refusal;
`missing-sample.json` retains an absent sample and `unresolved-identity.json`
retains an unresolved result identity; these cannot authorize result delivery; `multi-part-coded.json` covers multiple parts and coded values;
`withdrawn.json` covers a withdrawn observation. See the files for exact inputs.
